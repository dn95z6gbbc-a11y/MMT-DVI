# MMT ДВИ

Интерактивный прототип приложения для подготовки абитуриентов к поступлению на направления журналистики и к дополнительным вступительным испытаниям (ДВИ).

## Сейчас

- Версия прототипа: v0.11
- Четыре модели вузов: СПбГИКиТ, МПГУ, РАНХиГС и ГИТР
- Единый каталог, сравнение, личный план, динамическая Главная и календарь
- База MMT, медиасреда/повестка, письменные и устные тренажёры, симуляции собеседования
- Портфолио 2.0 и стажировка 2.0

## v0.10 — инфраструктура вузов

Введён единый реестр `MMT_UNIVERSITIES`. Каталог, сравнение, Главная и календарь читают данные из одной модели: город, программа, кампания, статус данных, источник, форматы ДВИ, портфолио, бюджет/стоимость при наличии, состояние «в плане» и календарные требования.

Формальная информация не переносится автоматически между приёмными кампаниями. Если новая дата, стоимость, число мест или проходной балл не подтверждены, поле остаётся пустым / «не внесено».

## v0.11 — портфолио 2.0

Портфолио стало единым реестром работ, а не набором отдельных папок.

Для каждой работы можно хранить:
- название
- жанр
- тип: учебная MMT / публикация в СМИ / авторский проект / институциональный материал
- статус публикации
- редакцию или площадку
- ссылку
- подтверждение
- дату

Работы затем сопоставляются с вузами из личного плана. Интерфейс специально не придумывает точный процент готовности, если актуальные требования вуза ещё не внесены.

Для ГИТРа используется известная по программе 2026 структура творческой папки: собственные журналистские материалы, автобиография, видеовизитка, а при наличии — дипломы/грамоты и рекомендации.

Для СПбГИКиТ пока показывается подбор MMT и наличие работ/подтверждений без выдуманного официального процента соответствия. Точные лимиты и состав нужно привязывать к актуальной программе кампании.

Добавлен отдельный гайд по оформлению: разделы, контекст каждой работы, отбор под вуз, проверка ссылок и резервная копия. Экспорт итогового PDF планируется после стабилизации требований вузов.

## v0.11 — стажировка 2.0

Стажировка связана с медиасредой пользователя:

1. выбрать редакцию;
2. изучить её материалы;
3. подготовить персональное обращение;
4. приложить портфолио и предложить темы;
5. зафиксировать статус обращения.

Есть конструктор структуры письма и трекер редакций со статусами:
- планирую
- письмо готово
- отправлено
- ответили
- договорились

Региональный контур из блока «Медиасреда и повестка» переиспользуется как источник кандидатов для будущей практики.

## Техническая уборка v0.11

Частые итерации прототипа — ожидаемый этап разработки, но после v0.10 стало важно уменьшить технический долг.

Первый безопасный этап рефакторинга выполнен:
- вложенная цепочка загрузки `v05.js → v06.js → ...` заменена manifest-loader в `app.js`;
- список модулей теперь задаётся в одном месте;
- после загрузки всех модулей создаётся событие `mmt:ready`;
- общие данные о вузах должны использовать `MMT_UNIVERSITIES`, а не дублироваться в каждом новом экране;
- добавлен `ARCHITECTURE.md` с правилами дальнейшей разработки.

Полное механическое объединение всех старых модулей сейчас намеренно не делается: пока UX активно меняется, это создало бы лишний риск регрессий. Второй этап рефакторинга нужен перед настоящей Android-разработкой — общий store/data layer, UI-компоненты и feature-модули.

## Принцип данных

- МПГУ: примеры, полученные от ученицы, не маркируются как официальный источник.
- РАНХиГС: программа ДВИ лета 2026; банк тренировок ещё требует содержательной ревизии.
- ГИТР: используется загруженная программа ДВИ 2026.
- Архивные даты 2026 не считаются датами следующей кампании.

## Что дальше

После UX-теста v0.11 основная ценность уже не в бесконечном добавлении экранов. Следующие крупные этапы:
1. содержательная ревизия тренажёров и критериев;
2. полноценная редакторская админка;
3. второй этап технического рефакторинга;
4. после стабилизации ключевых сценариев — настоящее Android-приложение.
